# Validation

`ocp app validate` runs the `@optimizely/ocp-cms-ui-extensions-sdk` plugin, which validates the `ui_extensions` block in `app.yml` and cross-checks it against the entry files on disk. All checks are fail-loud — validation returns the full list of problems.

## Rules enforced

Across the **entire** `ui_extensions` block (not per injection point):

| Rule | Error surfaced |
| --- | --- |
| `name` unique across all injection points | `Invalid app.yml: ui_extensions duplicate name: <name>` |
| `entry_point` unique across all injection points | `Invalid app.yml: ui_extensions duplicate entry_point: <entry_point>` |
| `display_name` non-blank | `Invalid app.yml: ui_extensions.<injectionPoint>.<name> display_name must not be blank` |
| Each declared `entry_point` has a matching entry file | entry-file validation error naming the missing file |
| Injection-point key is one of `UI_EXTENSION_INJECTION_POINTS` | schema rejects unknown keys (`additionalProperties: false`) |
| Item has only `name` / `entry_point` / `display_name` / `metadata` | schema rejects unknown item fields |
| `property-editor` item declares `metadata.property_type` | `Invalid app.yml: ui_extensions.property-editor.<name> metadata.property_type is required for a property-editor extension. Must be one of: string, richtext, integer, float, boolean` |
| `property_type` is supported | `Invalid app.yml: ui_extensions.property-editor.<name> metadata.property_type '<type>' is not supported. Must be one of: string, richtext, integer, float, boolean` |
| `property_format` is valid for the type | `Invalid app.yml: ui_extensions.property-editor.<name> metadata.property_format '<fmt>' is not valid for property_type '<type>'. Must be omitted` (or `omitted or one of: shortstring` for `string`) |

The uniqueness of `entry_point` is global because the CDN bundle path is keyed only by `entry_point` — two extensions with the same `entry_point` would overwrite each other's bundle.

## Common errors and fixes

- **"duplicate entry_point"** — two items share an `entry_point`, possibly under different injection points. Give each a distinct `entry_point` (and rename the matching entry file).
- **"display_name must not be blank"** — an item is missing or has an empty `display_name`.
- **Entry file not found** — the entry file name doesn't match `<entry_point>.<injectionPoint>.tsx`, or lives outside the extensions root. Fix the file name/location so the `<EntryPoint>` and `.<injectionPoint>.` segments line up with `app.yml`.
- **Unknown injection point** — you used a surface not in `UI_EXTENSION_INJECTION_POINTS` (e.g. `toolbar`). Remove it; only `sidebar`, `view` and `property-editor` are currently supported. If `property-editor` itself is rejected, the app's `@optimizely/ocp-cms-ui-extensions-sdk` is older than 1.1.0-beta.1 — upgrade it.
- **Schema rejects a field** — an item has a key beyond `name` / `entry_point` / `display_name` / `metadata`. Remove it. If `metadata` is rejected, upgrade `@optimizely/ocp-cms-ui-extensions-sdk` to >= 1.1.0-beta.1.
- **"metadata.property_type is required"** — a `property-editor` entry has no `metadata.property_type`. Add one from the supported list.
- **"property_type '…' is not supported"** — the type is outside `string | richtext | integer | float | boolean`. There is no way to target other types yet; pick a supported one.
- **"property_format '…' is not valid"** — only `string` accepts a format (`shortstring`). Remove `property_format` for every other type.

## Where the rules live

- The injection-point set: `UI_EXTENSION_INJECTION_POINTS` (single source of truth) in `@optimizely/ocp-cms-ui-extensions-sdk`.
- The generated JSON schema: derived from that tuple with `additionalProperties: false` (do not hand-edit; it is regenerated by the SDK build).
- The uniqueness / non-blank / entry-file / property-type checks: the plugin's validators, run automatically during `ocp app validate`.
- The supported property types: `ALLOWED_PROPERTY_TYPES` in `@optimizely/ocp-cms-ui-extensions-sdk`.

## Local testing

Passing validation does not by itself confirm the extension renders. Use the `ocp-local-testing` skill (`ocp dev`) to mount and exercise the extension in a browser before publishing. The local testing tool renders `sidebar` and `view` only; it does not render `property-editor` yet, so verify a property editor in a CMS instance after publishing.
